#   .venv\Scripts\python -m pip install -r requirements.txt --extra-index-url https://download.pytorch.org/whl/cu121

# Version contract (UNITY_RULES §4): the Python trainer and the C# package must
# agree on the communication protocol or the handshake is refused.
#
#   com.unity.ml-agents  4.1.0   ->  comms API 1.5.0
#   mlagents             1.1.0   ->  comms API 1.5.0     <- equal, handshake OK
#
# 4.1.0 is newer than the release_23 tag (4.0.0) but did not move the protocol.
# If you bump either side, re-check Academy.cs `k_ApiVersion` against
# mlagents_envs.environment.UnityEnvironment.API_VERSION before training.

# --- Trainer -----------------------------------------------------------------
mlagents==1.1.0
mlagents-envs==1.1.0

# --- Torch (CUDA 12.1 build) -------------------------------------------------
# Needs the PyTorch index; the plain PyPI wheel is CPU-only.
#
# DO NOT UPGRADE THIS. torch 2.11.0+cu128 was installed and reverted the same day.
# It ran fine for 80,000 steps and then killed the run at the first checkpoint:
#
#     ModuleNotFoundError: No module named 'onnxscript'
#
# torch >= 2.6 exports ONNX through onnxscript, and onnxscript pulls onnx>=1.17,
# which pulls numpy 2.x and protobuf 7.x — every load-bearing pin below. mlagents
# 1.1.0 needs onnx 1.15.0, numpy 1.23.5 and protobuf 3.20.3, so the export path and
# the trainer cannot both be satisfied. Promotion depends on that .onnx export, so a
# trainer that cannot write one is useless however fast it runs.
#
# The upgrade bought nothing anyway. This machine has an RTX 5070 Ti (Blackwell,
# sm_120) and cu121 has no kernels for it, but training runs on the CPU by choice:
# measured over steps 20k->60k with 6 headless envs, the CPU does 337 steps/s and the
# GPU does 55 — 6x slower, because the net is 512 x 2 at batch 2048 and launch
# overhead beats the matmuls.
#
# Launch every run with CUDA_VISIBLE_DEVICES=-1. Neither --torch-device=cpu nor
# torch_settings.device: cpu works alone: mlagents/torch_utils/torch.py calls
# set_torch_config(TorchSettings(device=None)) at import, resolves it to "cuda"
# whenever a GPU is visible, and its cpu branch never restores torch's default
# device. Use -1; "" is ignored on Windows.
torch==2.5.1+cu121

# --- Pins that are load-bearing, not incidental ------------------------------
# setuptools 81 removed pkg_resources, which mlagents.torch_utils imports at
# module scope. Anything >=81 breaks `mlagents-learn` on startup.
setuptools<81

# mlagents hard-pins these; listed so a resolver cannot drift them upward.
numpy==1.23.5
protobuf==3.20.3
grpcio==1.48.2
onnx==1.15.0

# --- Telemetry ---------------------------------------------------------------
tensorboard>=2.14
