# Version contract (UNITY_RULES §4): the Python trainer and the C# package must
# agree on the communication protocol or the handshake is refused.

#   com.unity.ml-agents  4.1.0   ->  comms API 1.5.0
#   mlagents             1.1.0   ->  comms API 1.5.0     <- equal, handshake OK
#
# 4.1.0 is newer than the release_23 tag (4.0.0) but did not move the protocol.
# If you bump either side, re-check Academy.cs `k_ApiVersion` against
# mlagents_envs.environment.UnityEnvironment.API_VERSION before training.

# --- Trainer -----------------------------------------------------------------
mlagents==1.1.0
mlagents-envs==1.1.0

# --- Torch (CUDA 12.8 build) -------------------------------------------------
# Needs the PyTorch index:
#   pip install torch --index-url https://download.pytorch.org/whl/cu128
#
# Was torch==2.5.1+cu121, pinned for an RTX 2060. This machine has an RTX 5070 Ti
# (Blackwell, sm_120); cu121 ships no kernels for it, so every run died building the
# first Linear layer with "CUDA error: no kernel image is available for execution on
# the device". 2.11.0+cu128 runs on the card correctly.
#
# BUT TRAINING STILL RUNS ON THE CPU, AND THAT IS DELIBERATE. Measured on this
# machine, 6 headless envs, steps 20k->60k:
#
#     CPU              337 steps/s
#     RTX 5070 Ti       55 steps/s      <- 6x SLOWER
#
# The network is 512 units x 2 layers at batch 2048. Kernel-launch overhead and host
# transfers cost more than the matmuls save, so the GPU loses badly. Revisit only if
# the network grows a lot.
#
# Launch every run with CUDA_VISIBLE_DEVICES=-1. Neither --torch-device=cpu nor
# torch_settings.device: cpu works on its own: mlagents/torch_utils/torch.py calls
# set_torch_config(TorchSettings(device=None)) at import, resolves it to "cuda"
# whenever a GPU is visible, calls torch.set_default_device("cuda"), and its cpu
# branch never puts the default back. Use -1; "" is ignored on Windows.
torch==2.11.0+cu128
