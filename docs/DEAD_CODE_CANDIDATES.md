# Dead-Code Candidates

_Generated by `Tools/audit_dead_code.py` — reference-based, not behaviour-based._

Each row is a type whose declaration file is the ONLY file in the project that
even names the type as a token. Generics in constraints, reflection, and factory
registration are unobserved by this filter; the output is a starting list, not a
verdict.

---

## Verified 2026-09-08: every candidate was a false positive

All 23 rows of the previous run were checked by hand against scene GUIDs,
inheritance, call sites and `[MenuItem]` attributes. **None of them was dead.**
Nothing was deleted as a result of this audit.

The filter is blind to five ways a type is reached, and between them they
account for every row it produced:

| How the type is really reached | Rows it explained | Example |
|---|---|---|
| Attached to a GameObject in a scene — referenced by GUID in `.unity`, never by name in C# | 6 | `Systems_MenuView` (SCN_MENU), `Agent_Telemetry` (SCN_TRAIN_FOOTBALL) |
| Reached only through `[MenuItem]`, so the Editor calls it and no C# file does | 2 | `Editor_DeadBrainRefCleaner`, `Editor_MissingScriptCleaner` |
| An abstract base, named in an inheritance list rather than "used" | 1 | `Systems_ScreenView` — `Systems_HudView`, `Systems_MenuView` and `Systems_PerformanceOverlayView` all derive from it |
| An extension-method container, invoked as `x.Method()` so the class name never appears | 1 | `Systems_TeamIdExtensions` — `.Opponent()` has 10 call sites in `Systems_GameFlowSystem` alone |
| NUnit fixtures, discovered by attribute | 13 | every `*Tests` row |

Verification method, if this needs repeating:

```bash
# Is the type on a GameObject in a scene? Compare the script's .meta GUID
# against the scene YAML — this is the check the audit cannot do.
guid=$(grep -oE "guid: [0-9a-f]{32}" Assets/Scripts/.../Foo.cs.meta | head -1 | cut -d' ' -f2)
grep -l "$guid" Assets/Scenes/*.unity

# Is it reached from a menu?
grep -n "MenuItem" Assets/Editor/Foo.cs

# Is it an extension container? Search for the METHOD, not the class.
grep -rn "\.Opponent()" Assets --include=*.cs
```

**Do not delete a row from this file's table without running all four checks.**
The one time a brain set was deleted on a reference-based argument alone, the
provenance had to be reconstructed afterwards from
[results/football_base02/MANIFEST.md](../results/football_base02/MANIFEST.md).

## What the audit is still good for

It is a cheap way to catch a type that genuinely lost its last caller — a
System that was replaced, a Model that stopped being read. Treat a row as "go
and check this one", not as "this is unused". A run that produces rows is
normal; a run that produces rows worth acting on is rare.
